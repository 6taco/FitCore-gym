# 健身房管理系统整体架构面试回答

## 1. 项目整体架构怎么理解？

这个项目是一个典型的前后端分离的全栈管理系统，整体可以分为三层：前端层、后端层和数据库层。

前端使用 React 18、Vite、TypeScript 和 Ant Design，主要负责页面展示、用户操作、表单提交、路由跳转、权限菜单展示等。

后端使用 Node.js、Express 和 Sequelize，主要负责接口服务、登录鉴权、权限校验、业务逻辑处理、参数校验、操作日志以及数据库访问。

数据库使用 MySQL 8，主要负责持久化保存业务数据，例如用户、角色、权限、会员、会员卡、课程、预约、订单、支付、库存、签到等。

通俗地说，前端就像系统的“操作界面”，用户在页面上点击按钮、填写表单；后端就像“业务处理中心”，负责判断这个操作是否合法、权限够不够、数据是否正确；数据库就像“档案室”，最终把会员、课程、订单等数据保存起来，并在需要时查询出来返回给前端。

所以这个项目的整体协作方式是：用户在前端操作，前端通过 HTTP 请求调用后端接口，后端处理业务逻辑并通过 Sequelize 操作 MySQL 数据库，数据库返回结果后，后端再把统一格式的 JSON 数据返回给前端展示。

## 2. 每一层分别负责什么？

### 2.1 前端层负责什么？

前端主要负责用户看得见、点得到的部分。

本项目的前端目录是 client，主要技术包括 React 18、Vite、TypeScript、Ant Design、React Router、Zustand、Axios 和 ECharts。

前端主要职责包括：

第一，页面展示。比如登录页、会员管理、课程管理、收银台、订单管理、财务报表、数据看板等页面。

第二，用户交互。用户点击新增会员、课程预约、办卡、签到、退款等按钮，都是由前端页面负责响应。

第三，表单收集。比如新增会员时，前端负责收集姓名、手机号、生日、标签、备注等信息。

第四，接口调用。前端通过 Axios 向后端发送 HTTP 请求，项目中统一封装在 client/src/api/request.ts 中。

第五，登录状态管理。用户登录成功后，前端保存 token、refreshToken 和用户信息。后续请求接口时，请求拦截器会自动在请求头里带上 Authorization: Bearer token。

第六，权限相关展示。前端会根据登录用户的角色和权限，控制菜单、按钮、页面是否可见。

简单来说，前端负责“让用户操作系统”，但它不直接操作数据库。

### 2.2 后端层负责什么？

后端主要负责业务逻辑和接口服务。

本项目的后端目录是 server，主要技术包括 Node.js、Express、Sequelize、JWT、Zod、Winston 和 node-cron。

后端主要职责包括：

第一，提供接口。比如 /api/auth/login、/api/members、/api/courses、/api/orders、/api/dashboard 等。

第二，登录鉴权。项目使用 JWT 判断用户是否登录。前端请求时带上 token，后端解析 token 得到当前用户身份。

第三，权限控制。项目采用 RBAC 权限模型，用户属于某个角色，角色拥有多个权限。比如只有拥有 member:create 权限的人才能新增会员。

第四，参数校验。后端使用 Zod 对前端传来的参数进行校验，避免非法数据进入数据库。

第五，业务逻辑处理。比如新增会员时自动生成会员编号，办卡时生成会员卡，课程预约时检查容量，退款时回滚库存，签到时生成签到记录。

第六，数据库操作。后端通过 Sequelize 模型操作 MySQL，不让前端直接接触数据库。

第七，统一响应。后端接口一般返回统一结构，例如：

{
  "code": 0,
  "message": "ok",
  "data": {}
}

简单来说，后端负责“判断能不能做、怎么做、做完怎么存”。

### 2.3 数据库层负责什么？

数据库主要负责长期保存业务数据。

本项目使用 MySQL 8，数据库脚本在 db/schema.sql 中。

核心表包括：

用户权限相关表：users、roles、permissions、role_permissions。

会员相关表：members、body_measurements、membership_plans、memberships。

课程预约相关表：coaches、courses、course_schedules、bookings、course_reviews。

商品库存订单相关表：products、stock_movements、orders、order_items、payments。

系统扩展相关表：notifications、check_ins、audit_logs、settings。

简单来说，数据库负责“把系统里的核心业务数据稳定保存下来”。

## 3. 数据是如何从前端流到数据库再返回的？

这里可以用“新增会员”这个功能来举例。

### 3.1 用户在前端填写表单

前台工作人员进入会员管理页面，点击“新增会员”，填写会员姓名、手机号、性别、生日、标签、备注等信息，然后点击提交。

前端页面会收集表单数据，然后调用前端 API 方法 apiMemberCreate。

这个方法最终会通过 Axios 发送请求：

POST /api/members

### 3.2 前端请求自动带上 token

因为新增会员是需要登录后才能操作的功能，所以前端请求拦截器会自动在请求头里带上：

Authorization: Bearer 用户登录token

这样后端就知道当前是谁在操作。

### 3.3 请求进入后端 Express

请求先进入后端入口 server/src/app.js。

后端把所有 API 都挂载在 /api 下，所以前端请求 /api/members，会进入后端会员相关路由。

新增会员对应的后端路由是：

POST /members

实际完整路径就是：

POST /api/members

### 3.4 后端进行登录校验和权限校验

请求进入业务处理前，后端会先做登录校验和权限校验。

第一步，authRequired 中间件检查 token 是否有效。如果 token 无效，就返回未登录或登录已失效。

第二步，requirePermission 中间件检查当前用户是否拥有 member:create 权限。如果没有权限，就拒绝操作。

第三步，audit 中间件会记录操作日志，比如谁在什么时候新增了会员。

### 3.5 后端控制器处理业务逻辑

通过登录和权限校验后，请求会进入 memberController.js 里的 createMember 方法。

这个方法主要做几件事：

第一，使用 Zod 校验前端传来的参数，比如姓名不能为空、手机号长度不能超过限制、状态值是否合法等。

第二，自动生成会员编号，例如以 M 开头的会员编号。

第三，如果会员关联了登录账号，会检查这个账号是否已经绑定过其他会员，防止重复绑定。

第四，调用 Sequelize 的 Member.create 方法创建会员数据。

### 3.6 Sequelize 写入 MySQL

Sequelize 会把后端的创建操作转换成数据库插入操作，最终把会员数据写入 MySQL 的 members 表。

members 表里会保存会员编号、姓名、手机号、生日、身高体重、标签、状态、创建时间、更新时间等字段。

### 3.7 数据库结果返回给后端

MySQL 插入成功后，会返回新会员的 id 和 member_no。

后端再包装成统一响应格式，例如：

{
  "code": 0,
  "message": "已创建",
  "data": {
    "id": 1,
    "member_no": "Mxxxx"
  }
}

### 3.8 前端收到结果并刷新页面

前端收到成功结果后，会关闭新增会员弹窗，提示创建成功，并重新请求会员列表。

最终，新创建的会员会显示在会员管理列表中。

所以完整链路可以总结为：

用户填写表单
↓
React 前端调用 API
↓
Axios 发送 /api/members 请求
↓
Express 后端接收请求
↓
JWT 登录校验
↓
RBAC 权限校验
↓
Controller 处理业务逻辑
↓
Sequelize 操作 MySQL
↓
MySQL 保存数据
↓
后端返回统一 JSON
↓
前端刷新页面展示结果

## 4. 如果面试官问“这个项目的技术架构”，应该怎么回答？

可以这样回答：

这个项目采用的是前后端分离架构。前端使用 React 18、Vite、TypeScript 和 Ant Design 搭建管理后台页面，负责页面展示、表单交互、路由跳转和接口调用。

前端通过 Axios 统一封装请求，请求地址以 /api 开头。开发环境下通过 Vite proxy 转发到后端服务，生产环境下通过 Nginx 转发到后端服务。

后端使用 Node.js 和 Express 搭建 RESTful API 服务，接口按照业务模块拆分，比如认证、会员、课程、财务、系统管理等模块。后端使用 JWT 做登录认证，使用 RBAC 做角色权限控制，使用 Zod 做参数校验，并通过 Sequelize ORM 操作 MySQL 数据库。

数据库使用 MySQL 8，主要存储用户、角色、权限、会员、会籍、课程、预约、商品、库存、订单、支付、签到、通知等业务数据。

部署上，项目支持 Docker Compose，一共包括三个核心服务：前端 Nginx 服务、后端 Node 服务和 MySQL 数据库服务。整体架构比较清晰，前端负责展示和交互，后端负责业务逻辑和安全校验，数据库负责数据持久化。

## 5. 面试官可能继续追问的问题

### 5.1 为什么说它是前后端分离？

可以回答：

因为前端和后端是两个独立项目。前端在 client 目录，负责页面；后端在 server 目录，负责接口。前端不直接访问数据库，而是通过 HTTP 请求调用后端 API。后端处理完业务后，再把结果以 JSON 形式返回给前端。

### 5.2 权限是怎么做的？

可以回答：

项目使用 RBAC 权限模型，也就是“用户 - 角色 - 权限”这种设计。用户表 users 关联角色表 roles，角色再通过 role_permissions 关联具体权限。用户登录后，后端会返回该用户的角色和权限列表。访问接口时，后端通过中间件判断当前用户是否拥有对应权限，比如新增会员需要 member:create 权限。

### 5.3 登录状态怎么保持？

可以回答：

登录成功后，后端生成 JWT token 和 refreshToken 返回给前端。前端保存 token，之后每次请求接口时，Axios 请求拦截器会自动把 token 放到请求头的 Authorization 字段里。后端收到请求后解析 token，如果 token 有效，就允许继续访问；如果 token 失效，前端会尝试用 refreshToken 刷新登录状态。

### 5.4 数据库和后端如何交互？

可以回答：

后端通过 Sequelize ORM 操作 MySQL。每张核心业务表在后端都有对应的模型，比如会员表对应 Member 模型，会员卡表对应 Membership 模型。控制器不直接拼接 SQL，而是调用模型的 findAll、findByPk、create、update、destroy 等方法完成增删改查。

### 5.5 这个项目有哪些业务模块？

可以回答：

这个系统覆盖了健身房常见业务，包括会员管理、会籍管理、卡种管理、课程排课、课程预约、教练管理、入场签到、商品库存、收银台、订单退款、财务报表、数据看板、通知中心和系统权限管理等模块。

## 6. 一句话总结

总体来说，这个项目是一个基于 React、Express 和 MySQL 的前后端分离健身房管理系统。前端负责交互展示，后端负责接口和业务逻辑，数据库负责数据持久化，并通过 JWT 和 RBAC 保证系统的登录安全和权限控制。
